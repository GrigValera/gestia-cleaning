# Гестия — лендинг клининговой компании

Адаптивный одностраничный сайт для демонстрации в портфолио и публикации на GitHub Pages. Проект сделан на HTML, CSS и JavaScript без клиентских библиотек и сборки. Загрузка не зависит от работающего сервера. Для приёма заявок предусмотрен отдельный серверный адаптер в `server/`.

> Это демонстрационный проект. Компания, цены, телефон, отзывы о процессе и доступность услуг требуют проверки и замены реальными данными перед коммерческим запуском. Фотографии сгенерированы ИИ и не изображают реальных сотрудников компании.

### Поля заявки

Обязательные: имя, телефон, тип услуги, согласие на обработку данных. Дополнительные: площадь, дата, район/адрес, комментарий, способ связи, email. Есть поле-ловушка для простого отсеивания ботов. На клиенте проверяются обязательные поля, формат email и длина телефона; сервер перепроверяет входящие данные.

Пока `leadEndpoint` пустой, форма **не отправляет персональные данные**. Она формирует текст заявки для просмотра и копирования. При подключённом обработчике форма выполняет HTTPS POST и сообщает об успехе только после ответа сервера.

## Запуск локально

Откройте `index.html` в браузере. Для проверки режима отправки и сетевых запросов удобнее локальный сервер:

```bash
python -m http.server 8080
```

Адрес: `http://localhost:8080/`. В папке сайта нет шага `npm install` или `build`.

## Публикация на GitHub Pages

1. Создайте новый публичный репозиторий, например `gestia-cleaning`, и скопируйте содержимое этой папки в его корень.
2. Отправьте файлы в ветку `main`.
3. После проверки проекта в GitHub откройте **Settings → Pages → Build and deployment**, выберите **GitHub Actions**. Запустите workflow `.github/workflows/pages.yml` вручную через **Actions → Publish to GitHub Pages → Run workflow**. Он не запускается автоматически при отправке изменений.
4. После появления публичного URL замените демонстрационные контакты и добавьте абсолютный canonical URL, `og:url`, `og:image` и `sitemap.xml`. Если нужен свой домен, добавьте `CNAME` и настройте DNS в Pages.

Статический GitHub Pages не исполняет серверный код. Папка `server/` — отдельный пример адаптера для размещения на платформе с Node.js. Секреты никогда не добавляются в репозиторий и не записываются в `config.js`.

## Подключение заявок

Подробный порядок настройки CRM, Telegram, email и SMS: [docs/integrations.md](docs/integrations.md). Кратко:

1. Разверните `server/` как HTTPS-сервис.
2. Включите один или несколько каналов через переменные окружения.
3. В `config.js` укажите URL вида `https://api.example.com/api/leads`.
4. Проверьте реальную тестовую заявку в каждом подключённом канале.

Вместо самостоятельной настройки можно передать разработчику `docs/integrations.md`, URL опубликованного сайта и доступы к выбранной CRM/сервисам через безопасный канал. Токены не нужно отправлять в переписке или хранить в GitHub.

## SEO и производительность

- Семантическая структура, один `h1`, логичная иерархия заголовков, метаописание, Open Graph, JSON-LD `CleaningService`, русская локаль.
- Фото преобразованы в JPEG с умеренным качеством: три файла суммарно около 650 КБ. Картинки ниже первого экрана загружаются лениво.
- Минимальный JavaScript, без больших библиотек, анимация учитывает `prefers-reduced-motion`.
- Относительные пути позволяют разместить сайт в подпапке репозитория Pages.

После публикации стоит проверить страницу через Lighthouse/PageSpeed Insights, подключить Search Console и Яндекс Вебмастер, добавить реальные юридические данные и политику обработки персональных данных. Мета-описания и локальные запросы следует уточнить под фактический район работы компании. Форма в рабочем режиме передаёт персональные данные, поэтому до включения приёма заявок нужна актуальная политика и согласие для реального оператора данных.
