# Как подключить заявки к CRM, Telegram, почте и SMS

GitHub Pages размещает только интерфейс. Приём заявок требует отдельного HTTPS-обработчика. В `server/index.mjs` уже подготовлен пример на Node.js 20+ без сторонних пакетов: он проверяет данные, ограничивает частоту запросов и пересылает заявку в выбранные каналы. Для публичного сервиса добавьте устойчивое хранение/очередь заявок, мониторинг и защиту от массового спама; встроенное ограничение частоты хранится только в памяти одного процесса.

## 1. Развернуть адаптер

Разместите папку `server/` на любой платформе, которая запускает постоянный Node.js-процесс и предоставляет HTTPS-адрес. Создайте переменные окружения по `server/.env.example`. Для локальной проверки скопируйте `.env.example` в `.env`, заполните значения и запустите:

```bash
cd server
npm start
```

Проверьте `GET /health`. Порт по умолчанию `8787`. `ALLOWED_ORIGIN` — точный origin сайта, например `https://grigvalera.github.io` (без пути репозитория и завершающего `/`). Для собственного домена укажите его origin. Не используйте `*` для публичного приёма заявок.

В `config.js` на сайте задайте:

```js
window.GESTIA_CONFIG = Object.freeze({
  leadEndpoint: 'https://ВАШ-АДРЕС-СЕРВЕРА/api/leads'
});
```

Дальше опубликуйте сайт и отправьте тестовую заявку. Убедитесь, что в браузере нет ошибки CORS, а в выбранном канале появилась заявка. Секреты храните только в переменных окружения сервера.

## 2. CRM

Укажите `CRM_WEBHOOK_URL` — URL HTTPS-вебхука вашей CRM или промежуточного сценария автоматизации. При необходимости укажите `CRM_BEARER_TOKEN`. Адаптер отправляет POST с JSON:

```json
{
  "source": "gestia-website",
  "receivedAt": "2026-10-08T10:00:00.000Z",
  "name": "Анна",
  "phone": "+7 999 000-00-00",
  "service": "Генеральная уборка",
  "area": "65",
  "date": "2026-10-12",
  "location": "Хамовники",
  "comment": "Нужно помыть окна",
  "contactMethod": "phone",
  "email": "",
  "consent": true,
  "website": ""
}
```

Если CRM требует другой формат, преобразуйте объект в функции `dispatch()` сервера или используйте промежуточный webhook. Сопоставьте поля с карточкой лида, настройте ответственого и статус «Новая заявка». Проверьте дубли и ошибки доставки. В текущем демо при частичном сбое каналов повторная отправка может создать дубль в уже успешном канале — для рабочего потока добавьте idempotency key и очередь задач.

## 3. Telegram-бот

1. Создайте бота через официальный `@BotFather` в Telegram и получите токен.
2. Добавьте бота в нужный чат/группу и разрешите отправку сообщений.
3. Узнайте `chat_id` вашего чата доступным вам способом через Telegram Bot API.
4. Укажите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в секретах сервера.
5. Отправьте тестовую заявку и убедитесь, что сообщение получено.

Бот здесь служит **каналом уведомлений**. Диалог с клиентом, команда бота и автоматический ответ клиенту не реализованы: для этого понадобится отдельная логика и согласованный сценарий общения. Не вставляйте токен в `config.js` или HTML.

## 4. Почта и SMS

`EMAIL_WEBHOOK_URL` и `SMS_WEBHOOK_URL` рассчитаны на ваш сервис автоматизации или собственный адаптер, принимающий тот же JSON, что и CRM. Если сервис требует Bearer-токен, используйте `EMAIL_BEARER_TOKEN` или `SMS_BEARER_TOKEN`. Для прямой работы с конкретным почтовым/SMS-провайдером добавьте преобразование запроса под его API на сервере; frontend менять не нужно.

Для уведомлений клиенту по email/SMS потребуется отдельный шаблон, адрес отправителя/номер, правила согласия и защита от повторных сообщений. Текущий пример отправляет данные только в настроенные каналы компании.

## 5. Проверка перед запуском

- Форма без заполненных обязательных полей не отправляется.
- С валидной заявкой сервер возвращает `200`, и уведомления попадают во все настроенные каналы.
- При отключённом канале и ошибке сети сайт показывает ошибку, не обещая доставку.
- Токены отсутствуют в публичном репозитории и DevTools браузера.
- Политика обработки персональных данных и тексты согласия соответствуют реальному оператору и способам обработки.
- Доступ к заявкам ограничен, сроки хранения и удаление данных определены владельцем бизнеса.

Если нужно подключение «под ключ», передайте разработчику адрес опубликованного сайта, название и доступы к CRM/сервисам через безопасный канал, желаемые поля сделки и маршруты уведомлений. Настройка конкретной CRM зависит от её API и бизнес-процесса.
